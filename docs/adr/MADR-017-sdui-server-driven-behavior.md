## Контекст

После MADR-015/016 сервер задаёт **композицию** экрана (какие блоки, порядок, данные), а
клиент держит **рендереры** блоков. Рендереры (виджеты) — неустранимый пол: клиент не
нарисует то, под что у него нет виджета. Но вокруг каждого блока клиент по-прежнему
**хардкодит знание трёх классов**, которое к компонентам не относится и могло бы жить на
сервере:

1. **Навигация** — тап карточки ведёт на захардкоженный роут (`context.push('/home/plants/:id')`);
   клиент держит карту роутов витрин.
2. **Бизнес-правила показа** — `isGuest`, `isEmptyGarden`, показывать ли guest-banner /
   push-priming / empty-state — ветвление на стороне клиента.
3. **Проводка** — список ключей инвалидации после мутации (MADR-004) захардкожен на клиенте
   и дублирует модель данных бэкенда; аналитика/телеметрия зашиты в обработчики.

Цель — сделать клиент **тупым исполнителем декларативных намерений**: навигация, видимость и
проводка приходят с сервера, клиент их исполняет, не зная бизнес-правил. Это «уровень 2.5» —
всё ещё block-SDUI (виджеты у клиента), полный SDUI (дерево примитивов) по-прежнему не нужен.

## Решение

Три аддитивных расширения опакового контракта (MADR-016). Все три ложатся на уже
существующий `ActionDescriptor` / структуру блока — новой философии не вводят.

### 1. Расширение словаря действий: `navigate`
- `ActionDescriptor.kind` прирастает значением `navigate` рядом с `log_care`:
  `{ kind: "navigate", target: "/plants/42" }` (или `{ screen, params }`).
- Клиент исполняет через существующий `ActionRunner` → `go_router`. Клиент перестаёт **знать
  карту роутов витрин** — он лишь резолвит `target` в навигацию.
- **Только read-heavy переходы.** Интерактивные флоу (wizard/sheet) по-прежнему открываются
  нативно (MADR-015), не через `navigate`.
- Неизвестный/невалидный `target` → no-op + лог (graceful), не краш.

### 2. Серверная видимость блоков
- Решение «включать ли блок» (guest-banner, empty-state, push-priming, сезонный промо)
  принимает **сервер** — он знает состояние юзера (гость/авторизован, пустой сад, право) — и
  просто **не кладёт** блок в `blocks[]`. Клиент перестаёт ветвиться на `isGuest`/`isEmptyGarden`.
- Парный приём — **явные state-блоки**: вместо клиентского инференса «сад пустой» сервер шлёт
  блок `empty_state { icon, copy_key, cta_action }`. Состояние становится таким же блоком, как
  данные; клиент не держит ветвление состояний.
- Композиция уже в таблице `ui_views` (MADR-016) — видимость становится частью гидрации строки
  под конкретного юзера.

### 3. Декларативная проводка в действии
- **Инвалидация:** `ActionDescriptor` несёт `invalidates: ["home", "today"]` — что обновить
  после мутации. Клиент исполняет по списку вместо захардкоженного набора ключей (MADR-004).
  Разрывает связь клиента с моделью данных бэкенда.
- **Аналитика (опционально):** блок/действие несёт `analytics: { event, params }`; у клиента
  generic-диспетчер. Убирает зашитую проводку трекинга.
- **Доступность действия:** сервер шлёт `action: null` / `disabled: true` как бизнес-правило
  («полить нельзя сегодня») — enable/disable решает сервер, не клиент.

## Граница (что остаётся нативным — НЕ двигаем)

Сознательно оставляем клиенту (двигать = ломать уже принятое):
- **Тема / токены / типографика** — клиентские (MADR-015). Сервер цвета/отступы не шлёт.
- **Текст UI-обвязки** — через `AppLocalizations` (MADR-012). Контент (имена растений) с
  сервера, но лейблы/кнопки/ошибки/`empty_state.copy_key` — **ключи l10n**, не готовый текст.
  Иначе ломается ru-only-инфраструктура, **offline** (нечего показать без сети) и a11y.
- **Интерактив с локальным state** (wizard, sheet ухода) — нативный, не через action.
- **Никакой Turing-complete логики в JSON** (MADR-016): `navigate`/`invalidates`/`visibility`
  — это **декларации намерений**, не ветвления/циклы. Желание «if/loop в payload» = сигнал,
  что фича нативная.

## Причины

- Убирает три реальные зависимости клиента, не трогая нативный фил: карту роутов, бизнес-правила
  показа, дублирование модели данных в ключах инвалидации.
- Аддитивно к MADR-016 (новые `kind`/поля), forward-compatible через `X-UI-Catalog-Version`:
  старый клиент не знает `navigate` → action скипается, тап — no-op (graceful).
- Клиент → тупой исполнитель деклараций; полный SDUI всё ещё не нужен.

## Последствия

- `ActionRunner` учится `navigate` (+ `invalidates`); `BlockRegistry` — блок `empty_state`.
- `screenLayoutProvider`/репозиторий — без изменений (контракт опаковый, новые поля парсит
  маппер руками, MADR-016).
- **Цена, принимается осознанно:**
  - **offline-деградация растёт** — навигация/видимость теперь зависят от свежего ответа; без
    сети клиент менее автономен, чем сейчас. Нужен кэш последнего layout (drift, MADR-009).
  - **поверхность версионирования растёт** — каждый новый `kind`/поле = совместимость старых
    клиентов; каждый `navigate.target` должен существовать в релизе клиента.
  - **отладка сложнее** — «кнопка ведёт не туда» теперь в строке `ui_views`, не в коде.
- **`contract-keeper`** добавляет в прозовый словарь (MADR-016): значения `kind`
  (`log_care`/`navigate`), поля `invalidates`/`visibility`/`disabled`, блок `empty_state`.
- Реализация — поэтапно: сперва `navigate` (наибольший выигрыш / наименьший риск), затем
  серверная видимость, затем декларативная инвалидация. Каждый этап — отдельный срез с тестом
  на graceful-degradation.

> **Отвергнутая альтернатива: оставить навигацию/видимость/проводку на клиенте.** Меньше
> поверхности контракта и лучше offline, но клиент остаётся связан с картой роутов и моделью
> данных бэкенда — менять переходы/видимость/сезонный контент без релиза нельзя. Выбран сдвиг
> поведения на сервер ради релиз-фри управления, ценой offline-автономности и версионирования.
> Возврат дешёвый: `navigate`/`invalidates` — аддитивные поля, их можно перестать слать.
>
> **Отвергнутая альтернатива: полный SDUI (дерево примитивов).** Дал бы и поведение, и вёрстку
> с сервера, но ценой типобезопасности/кодгена/нативного фила (см. MADR-015). Уровень 2.5
> (поведение декларативно, рендереры нативны) даёт большую часть выигрыша без этой цены.

## Реализованные формы (факт пилота)

Опаковый ответ `GET /api/v1/ui/home` (фрагменты). Тексты блоков видимости — **ключи l10n**, не
готовый текст (граница: текст-обвязка клиентская, MADR-012).

**Срез 1 — navigate.** Элемент `plant_grid` несёт два действия:
```json
{ "id":10, "name":"Монстера", "locationName":"Гостиная",
  "action":     { "kind":"navigate", "target":"/plants/10" },
  "waterAction":{ "kind":"log_care", "method":"POST", "path":"/care-events",
                  "payloadTemplate":{"plantId":10,"type":"WATER"}, "invalidates":["home","today"] } }
```
- `action` — тап тела карточки (навигация к деталям); `waterAction` — кнопка «полить».
- Клиент: `ActionRunner` резолвит `target` через `appRouterProvider` (go_router), `BuildContext`
  не нужен. Неизвестный `kind`/пустой `target` → no-op + лог.

**Срез 2 — серверная видимость.** Сервис инъектирует блоки по состоянию юзера (в таблицу
`ui_views` не выносится — это динамика):
```json
{ "type":"guest_banner", "titleKey":"home.guest.title", "bodyKey":"home.guest.body",
  "ctaAction":{"kind":"navigate","target":"/home/register"} }
{ "type":"empty_state", "iconKey":"home.empty.icon", "titleKey":"home.empty.title",
  "bodyKey":"home.empty.body", "ctaAction":{"kind":"navigate","target":"/home/add"} }
```
- `guest_banner` — только гостю (после `weather_strip`). `empty_state` — **заменяет** `plant_grid`
  при пустом саде. Клиент перестал держать `isGuest`/`isEmptyGarden`-ветвление в `home_screen`.
- Ключи (`titleKey`/`bodyKey`/`iconKey`) резолвятся клиентом через `resolveSduiTextKey`/
  `resolveSduiIconKey` (switch по известным ключам → `AppLocalizations`/`Icons`); неизвестный
  ключ → пустая строка / дефолтная иконка, не краш.

**Срез 3 — декларативная инвалидация.** Действия-мутации несут `invalidates` — логические ключи
словаря `home` / `today` / `plant`. Клиент маппит ключ → провайдер (`home`→`homeScreenLayoutProvider`,
`today`→`homeTasksProvider`, `plant`→`plantDetail/History/Streak(plantId)`); неизвестный ключ →
пропуск. Прежний хардкод-список ключей инвалидации (MADR-004) на клиенте удалён.

> **Граница CTA-навигации.** `navigate.target` карточек — витринный словарь (`/plants/{id}`).
> CTA блоков видимости ведут в **нативные флоу** (`/home/add` — мастер, `/home/register` —
> конвертация гостя): навигация туда декларативна, но сам флоу остаётся нативным (MADR-015).
