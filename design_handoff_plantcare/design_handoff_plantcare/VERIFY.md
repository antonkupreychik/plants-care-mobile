# VERIFY.md — сверка реализации со скриншотами

> Плейбук для агента (Claude Code и т.п.), который **уже реализовал экран** и должен убедиться, что он совпадает с эталоном из `screenshots/`.
> Эталоны сняты из дизайн‑прототипа `design/PlantCare.html` в нативной ширине **412 CSS‑px**, в темах **light** и **dark**. Карта файлов — `screenshots/INDEX.md`, детали экранов — `README.md` (раздел 4).

---

## 0. Принцип

Это **порт** HTML‑прототипа в Expo / React Native, а не пиксель‑копия. Поэтому сверяем не идеальное совпадение пикселей, а **дизайн‑намерение**:

- ✅ Должно совпадать: композиция, порядок блоков, иерархия размеров, цветовые токены, скругления, состояния (пусто/загрузка/ошибка), точные тексты (включая реплики растений от первого лица).
- 🟡 Допустимы отличия: суб‑пиксельные отступы, рендер шрифта на разных платформах, поведение скролла, нативные системные контролы (пикеры, клавиатура).
- ❌ Не должно отличаться: палитра (бери токены из `theme/tokens.ts` ← `design/screens.jsx`), наличие/отсутствие элементов, копирайт, light↔dark переключение.

## 1. Запуск проекта

```bash
# из корня мобильного репозитория
npm install            # или pnpm / yarn
npx expo start         # дев-сервер
# i — iOS-симулятор, a — Android-эмулятор
```

Если приложение ещё не подключено к бэкенду — гоняй на моках (те же данные, что в прототипе: Моника/Монстера, Фернандо/Папоротник, Колючка/Кактус, Сьюзи/Суккулент, Перси/Эпипремнум). Это позволит сверить вёрстку до готовности API (см. `api-contract.md`).

## 2. Как снять сопоставимый кадр

1. Запусти симулятор с шириной экрана ~**390–412 pt** (iPhone 14/15, Pixel 5). Эталон — 412 px, так что пропорции совпадут.
2. Дойди до нужного экрана (или временно отрендери его напрямую в дев‑роуте).
3. Сними скриншот **в обеих темах**:
   - iOS Simulator: `Cmd+S` (или `xcrun simctl io booted screenshot out.png`).
   - Android: `adb exec-out screencap -p > out.png`.
   - Тема: переключи системную (Settings → Display) или тумблер темы в приложении.
4. Открой рядом эталон `screenshots/light/<NN-slug>.png` и `screenshots/dark/<NN-slug>.png` и сравни по чек‑листу из §3.

> Эталоны показывают **контент‑область экрана целиком** (без статус‑бара устройства и без рамки телефона). При сравнении игнорируй системный статус‑бар и нижний gesture‑bar симулятора.

## 3. Чек‑лист сверки одного экрана

Для каждого экрана пройди по пунктам:

- [ ] **Структура** — те же блоки в том же порядке сверху вниз.
- [ ] **Заголовки** — Instrument Serif, акцентное `em`‑слово в `primary` (зелёный). Размеры по `README.md` §6 (H1 38–44, H2 28–36, H3 20–24).
- [ ] **Тело/подписи** — Plus Jakarta Sans; uppercase‑caption там же, где в эталоне.
- [ ] **Цвета** — фон `bg`, карточки `surface`, границы `line`, акцент `primary`, тревога/просрочка `terracotta`. Сверь именно токены, не «на глаз».
- [ ] **Скругления** — карточки 22–28, чипы/pill 999 или 18–20, sheet‑верх 30–32.
- [ ] **Иллюстрации** — те же растения (Monstera/Fern/Succulent/Pothos/Cactus), в тех же местах.
- [ ] **Копирайт** — тексты совпадают дословно, особенно **реплики растений от первого лица** в кавычках «…» (Instrument Serif italic).
- [ ] **Состояния** — кнопки, тумблеры, бейджи в нужном состоянии (вкл/выкл, выбран/нет, просрочено).
- [ ] **Dark‑тема** — переключается, мелкие подписи читаемы (токен `inkMute` подобран под контраст ~4:1).

Зафиксируй вердикт в таблице §4.

## 5. Особые случаи

- **05 Push** — это макет push‑payload (lock screen), а не экран приложения. Сверяй с конфигом `expo-notifications` (заголовок, тело = реплика растения, quick actions «Опрыскано / Через час / Вечером / Завтра»), не с UI‑экраном.
- **06 / 06a / 06b, 36** — bottom sheets / пикеры. В эталоне нарисован кастомный вид; в RN допустимо использовать нативный sheet/пикер, сохранив тексты, набор быстрых значений и палитру.
- **28 Загрузка** — shimmer‑скелетон. Сверяй расположение «костей» и наличие анимации мерцания, не конкретные кадры.
- **23 Тихие часы** — 24‑часовой циферблат (тихая/активная зоны). Проверь, что тихий интервал 22:00–8:00 показан дугой и совпадает с полями времени.
- **Экраны с состояниями** (29, 30, 31, 32, 33) — проверяются триггером соответствующего состояния (нет сети, пустой ответ, первый care‑event). Их легко пропустить — не забудь.

## 6. Что делать при расхождении

1. Сначала проверь **токены** — 90% расхождений в цвете/радиусе/шрифте лечатся правкой `theme/tokens.ts`, а не самого экрана.
2. Сверь **точные значения** в исходнике компонента: открой `design/<file>.jsx → <Component>` (колонка таблицы §4) и сравни числа (fontSize, padding, borderRadius, gap) напрямую — они переносятся 1‑в‑1.
3. Если расходится контент/порядок блоков — приведи к эталону; прототип считается источником истины по UI.
4. Если расходится поведение/данные — сверь с `api-contract.md` (раздел 12 — какие поля приходят с бэка, чего пока нет).

## 7. Готово, когда

- Все 43 строки матрицы §4 в обеих темах = `OK`.
- Палитра берётся из единого `tokens.ts`, а не зашита по месту.
- Реплики растений сохранены дословно и от первого лица.
- Тёмная тема переключается на каждом экране, мелкий текст читаем.
- Пройдены чек-листы §8 (a11y) и §9 (стресс-контент).

## 8. Доступность (по `A11Y.md`)

Прогнать на 5–6 ключевых экранах (главная, карточка, мастер, профиль, лента):

- [ ] **Dynamic Type ×1.3 и ×1.6** — текст растёт и переносится, сетка не ломается, ничего не обрезано «насовсем».
- [ ] **Хит-таргеты ≥ 44pt** — иконки-кнопки с `hitSlop`, тап по всей строке настроек/чекбокса.
- [ ] **VoiceOver/TalkBack** — у всех кнопок роль+label; реплики растений озвучиваются осмысленно; карточка растения = один элемент; иллюстрации скрыты от ридера.
- [ ] **Только цвет ≠ смысл** — просрочка/статус продублированы текстом и иконкой.
- [ ] **Reduced motion** — анимации из `MOTION.md` отключаются, функции работают.

## 9. Стресс-тест контентом (по `A11Y.md` §3, референс `Robustness.html`)

Подставить экстремальные данные и убедиться, что вёрстка держится:

- [ ] **Длинное имя** `«Замиокулькас замиелистный пёстролистный»` — обрезается многоточием в 1 строку, кнопка на месте.
- [ ] **Большой сад** (80+ растений) — списки/сетки скроллятся, нет тормозов (FlatList/виртуализация).
- [ ] **Экстремальные числа** — стрик `0` (валидно, не «—») и `1247` (4 знака влезают, выравнивание tabular-nums).
- [ ] **Длинная реплика растения** (4 строки) — переносится свободно, пузырь растёт, без обрезки.
- [ ] **Склонения** — 1 растение / 2 растения / 5 растений / 11 растений / 21 растение (функция `plural`).
- [ ] **Пустые состояния** — экраны 10, 30, 31, 32 показываются вместо «голой» вёрстки.
